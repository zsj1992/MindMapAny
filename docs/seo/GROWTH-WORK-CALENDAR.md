# MindMapAny 90 天产品增长工作日历

> 制定日期：2026-08-12。计划从 2026-08-17（周一）开始，连续 12 个工作周。
> 默认资源是一名全职负责人，每个工作日投入 4–6 小时；遇法定节假日或外部审核等待时，任务顺延但顺序不变。

## 90 天目标

这不是“发 24 篇博客”的内容排期，而是产品、SEO、转化和分发共用的一张执行表。

- 近期目标（90 天）：建立稳定的非品牌自然流量和可归因的付费漏斗，达到 50–150 个自然访问/天。
- 中期目标（6 个月）：达到 200–500 个真实访问/天，并把自然访问到付费的转化率提高到 0.3%–0.8%。
- 业务北极星：`每周来自自然搜索的成功生成次数`，不是单纯浏览量。
- 收入验证：自然流量能够完整走通 `落地页 → 开始生成 → 生成成功 → 注册/保存 → 价格页 → 结账 → 支付成功`。

## 当前基线

- 已有 PDF、Text、Webpage、DOCX、EPUB、PPTX 六个可用输入和对应公开工具页。
- 首页、工具页、价格页、博客、合规页和工作台已上线；`/app/*` 不参与索引。
- 英文为默认语言，中文、日文、韩文、西班牙文、德文、法文已有本地化营销页和工具页。
- GA4 已接入，已记录生成开始、成功和失败；商业漏斗事件仍不完整。
- GSC 已配置并提交主要 URL，但需要验证索引与查询数据是否持续进入。
- Creem 产品和支付代码已接入；商户审核、KYC/KYB、收款账户与真实付款闭环仍需最终确认。
- Chrome 插件已提交审核；公开入口保持隐藏，批准并实测后再开放。

## 任务标签和每日完成规则

- `[DATA]` 数据、分析和决策。
- `[CODE]` 产品或站点实现。
- `[CONTENT]` 页面、案例或文章。
- `[SEO]` 索引、内链、结构化数据和搜索优化。
- `[DIST]` 外链、社区和渠道分发。
- `[USER]` 必须由所有者完成的身份、付款或账号动作。

每天只把一个结果设为“必须完成”。当天结束前必须留下可检查的产物：代码提交、部署 URL、数据截图、内容草稿或外联记录。未通过验收的任务不计完成，不把它悄悄挪进“以后优化”。

## 每周五固定检查

1. 本周自然访问、非品牌展示、工具页 CTR。
2. 开始生成数、生成成功率、自然流量注册率。
3. 价格页访问、结账开始、支付成功和自然流量收入。
4. 新增/丢失索引、404、canonical、hreflang 和 sitemap 异常。
5. 本周发布页面是否有实际示例、内部链接、CTA 和可验证来源。
6. lint、test、build、关键 URL 冒烟是否通过。

## 优先级保护规则

- P0：付款不可用、生成失败、数据无法归因、核心页面不收录。出现时暂停日历先修复。
- P1：六个工具页、研究论文簇、比较页、用例页和转化漏斗。
- P2：博客、外链、基准报告和多语言深化。
- P3：新功能、新输入类型、新语言、批量页面。只有 P0/P1 稳定后才能做。
- Chrome 插件获批前不公开宣传；获批后先完成安装、登录、抓取、生成、商店隐私披露的端到端测试，再把入口重新开放。

## 90 天验收表

| 指标 | 90 天目标 |
|---|---:|
| 核心工具页有效索引率 | ≥ 90% |
| 自然访问/天 | 50–150 |
| 工具落地页 → 开始生成 | ≥ 25% |
| 开始生成 → 生成成功 | ≥ 70% |
| 自然访问 → 注册 | ≥ 5% |
| 自然访问 → 付费 | 初期 ≥ 0.3% |
| 有真实数据的比较/案例/研究资产 | ≥ 6 个 |
| 有效相关域外链 | ≥ 10 个 |

目标不是为了在第 60 个工作日“做完 SEO”，而是得到一个每周可以重复的增长系统：数据指出机会，产品承接需求，内容解释差异，分发建立权威，收入验证优先级。
