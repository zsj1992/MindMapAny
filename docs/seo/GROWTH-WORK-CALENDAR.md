> “工作日”只表示任务顺序；自动任务每天继续推进下一项，不因周六、周日暂停。
> 默认资源是一名负责人，每天投入 4–6 小时。外部审核、付款或账号动作被阻塞时，继续完成不依赖该阻塞的任务。

## 90 天目标

这不是“发多少篇博客”的排期，而是需求研究、产品、SEO、转化和分发共用的一套增长系统。

- 近期目标（90 天）：建立稳定的非品牌自然流量和可归因的付费漏斗，达到 50–150 个自然访问/天。
- 中期目标（6 个月）：达到 200–500 个真实访问/天，自然访问到付费的转化率达到 0.3%–0.8%。
- 业务北极星：`每周来自自然搜索的成功生成次数`，不是单纯页面浏览量。
- 收入验证：自然流量能够走通 `搜索落地页 → 开始生成 → 生成成功 → 注册/保存 → 价格页 → 结账 → 支付成功`。

## 规划原则：先证明需求，再创建页面

所有 SEO 页面都按下面的顺序产生，禁止跳过前四步直接写页面：

1. **收词**：GSC、Google 自动补全与相关搜索、Google Ads Keyword Planner、Google Trends、竞品排名页和相关平台搜索建议。
2. **补数据**：记录地区、语言、搜索量区间、趋势、CPC、竞争度和现有 GSC 表现。多个来源冲突时保留来源，不伪造“精确值”。
3. **清洗**：删除不相关词；合并拼写、单复数和表达不同但任务相同的词；标记产品当前无法满足的需求。
4. **判定意图**：人工抽样 Google Top 10，记录工具页、栏目页、文章页、比较页等实际结果类型，而不是仅靠关键词字面猜测。
5. **聚类与映射**：一个真实任务对应一个主 URL；同义词合并到同一页，需求明显不同才拆页。
6. **排优先级**：优先做有需求、有产品能力、有商业价值且我们能提供独特证据的页面。
7. **制作与内链**：页面必须能完成用户任务；文章只做解释、验证和辅助，不替代工具。
8. **发布后学习**：用 GSC 查询、页面行为和生成成功率决定更新、合并、扩展或停止。

## 关键词母表与 URL 决策表

第 2–3 周建立 `docs/seo/KEYWORD-MASTER.csv` 和 `docs/seo/URL-DECISIONS.md`。关键词母表至少包含：

| 字段 | 说明 |
|---|---|
| keyword / locale / country | 原始搜索词、语言和目标地区 |
| source / collected_at | GSC、Ads、Trends、竞品或搜索建议及采集日期 |
| search_volume / trend / cpc | 可验证的数据；没有数据时留空，不估造 |
| intent / serp_page_type | 用户任务与 Top 10 主导页面类型 |
| cluster | 需求簇；同义表达进入同一簇 |
| product_fit | 当前是否能够真实完成任务及限制 |
| existing_url | 已有承接页面，避免重复 URL |
| proposed_url / page_type | 候选 URL 与首页、栏目、工具、用例、比较或文章类型 |
| priority / evidence | 做、合并、观察、暂不做及决策依据 |

页面优先级不只按搜索量排序，采用：

`机会分 = 可验证需求 × 商业/任务意图 × 产品匹配 × 可差异化程度 × 生成成功率 ÷ 实现与竞争成本`

## 新页面发布闸门

任何新增可索引 URL 必须同时通过以下检查，否则保持草稿、合并进现有页或暂不做：

- [ ] 有至少一个可记录的数据来源证明需求，不以 AI 猜测搜索量。
- [ ] 抽样 SERP 已确认应做的页面类型；工具意图不能只交付博客文章。
- [ ] 已检查现有 URL，不与同义词或相同任务互相蚕食。
- [ ] 产品当前能够完成承诺的任务，且有固定样本可复现。
- [ ] 页面有独立价值：可操作工具、真实示例、限制、验证方法、CTA，而不是换标题的模板页。
- [ ] URL、主关键词、次关键词、canonical、结构化数据和内链入口已经记录。
- [ ] 发布后有 GSC/GA4 验收日期与“保留、更新、合并、noindex”标准。

第一轮新增页面上限为 **5–10 个候选中的 1–3 个已验证页面**；不因词表很大批量制造薄内容。

## 每周固定检查

1. 新增关键词是否有来源、日期、地区和语言，是否误把工具估算值当真值。
2. 新候选 URL 是否通过 SERP 页面类型验证和发布闸门。
3. 本周非品牌展示、工具页 CTR、落地页→生成和生成成功率。
4. 注册、价格页、结账、支付成功和自然流量收入。
5. 新增/丢失索引、404、canonical、hreflang、sitemap 和孤立页异常。
6. 已发布页面是否有真实功能/示例、限制、内链、CTA 和可验证来源。
7. lint、test、build 和关键路径冒烟是否通过。

## 优先级保护规则

- P0：付款不可用、生成失败、数据无法归因、核心页面不收录。出现时暂停日历先修复。
- P1：关键词母表、搜索意图与 URL 决策、六个现有工具页、转化漏斗。
- P2：经数据验证的新需求簇、比较页、真实用例、原创基准资产。
- P3：泛博客、新输入、新语言和批量页面。只有 P0/P1 稳定且发布闸门通过后才做。
- Chrome 插件获批前不公开宣传；获批后先完成安装、登录、抓取、生成和商店隐私披露的端到端测试。
- 不因日历预先写了某个主题就强行发布；搜索意图或产品能力不支持时，允许用“更新现有页/不创建 URL”完成当天正确决策。
