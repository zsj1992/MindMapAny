# Mapify 公开站点架构对比

调研日期：2026-08-08。分析范围为公开可抓取页面，不涉及会员数据和登录态功能。

## 观察结果

Mapify 将网站拆成三个层次：公开产品与工具页、内容与用例页、`/app` 工作台。其 robots.txt 阻止搜索引擎抓取工作台，公开 sitemap 则覆盖多语言主页、工具、博客、用例和商业页面。英语 sitemap 观察到约 145 个 URL，其中约 115 个为博客相关 URL、17 个为工具 URL，并为 19 个地区/语言维护 sitemap。

主要公开目录包括：

- `/tools/*`：PDF、YouTube、音频、文章、网页、Markdown、研究论文等独立工具入口。
- `/blog/*`：教程、产品更新、比较、用例与行业内容。
- `/use-cases/*`：面向教育等具体场景。
- `/pricing`、`/faq`、`/browser-extension`、`/deep-research`：商业与功能实体页。
- `/app/*`：交互产品，不参与公开索引。

## 与 MindMapAny 的差距

| 维度 | 旧架构 | 本轮架构 | 后续机会 |
|---|---|---|---|
| 工具关键词 | `/app/{kind}` 薄页面 | `/tools/*` 独立落地页 | 扩展音频、PPT、论文等真实能力 |
| 信息型内容 | 无博客 | `/blog` + 3 篇种子文章 | 按关键词簇稳定发布 |
| 工作台索引 | 部分允许抓取 | `/app/*` 全部 noindex | 保持产品态与搜索态隔离 |
| 内链 | 首页到工作台 | 首页→工具→工作台，博客→工具 | 增加相关推荐模块 |
| 多语言 | 中文单站 | 保持中文单站 | 有本地化产能后再建 locale 目录 |
| 规模 | 页面少 | 可扩展内容模型 | 先质量后数量，避免复制竞品 URL 数量 |

## 不直接复制的部分

- 不为了 URL 数量提前生成几十个能力尚不存在的工具页。
- 不创建空分类、薄标签和自动拼接关键词页面。
- 不用品牌词或未经验证的比较结论作为主要增长策略。
- 不在没有本地化编辑能力时复制 19 种语言。
